Слайд 1 — Введение

Что мы строим

Telegram-платформа, которая постепенно замещает ручную координационную работу менеджера в команде ассистентов.

🎯 Цель

Автоматизировать полный цикл работы с ассистентом — от первого отклика на HR-воронку до закрытия оплачиваемой задачи и пересмотра ставки.

⚙️ Стек

  • OpenClaw — мульти-агентный фреймворк (gateway на ПК)
  • Neon Postgres — данные кандидатов, FSM, оценки, audit log
  • OpenRouter — модели Claude Sonnet 4.6 / Haiku 4.5 / Opus 4.7
  • Python aiogram 3 — TG-бот
  • Хостинг: локально на ПК (MVP), потом VPS
❓ Главные открытые вопросы для созвона
  • Профиль ассистентов — универсалы или AI-эксперты?
  • Тестовые задания — финальный текст Дмитрия или Коля переделывает?
  • Распределение задач — кнопки в личке (наша позиция) vs реакции в общем чате (в документах)?
  • Ревью — обязательная часть v1 (как в документах) или v2?
  • Граница MVP — где наша зона заканчивается?

📊 Что работает «только на скелете» если ИИ упадёт
  • Анкета → 4 жёстких вопроса вместо живого диалога
  • Выбор теста → случайно из библиотеки под направление
  • Оценка → задача складывается Дмитрию на ручную проверку
  • Распределение → round-robin по очереди
  • Дайджест → шаблонная таблица из БД
❓ Вопросы Дмитрию по принципу
  • Согласен с этим подходом? Первые недели MVP — много ручных нажатий с твоей стороны
  • Готов быть «оператором» 2-4 недели пока ИИ-агенты не введены?
  • Когда ИИ ошибётся — как откатываем? Нужна админ-команда?
🛠 Стратегия фаз разработки
  • Фазы 1-3: скелет полностью (без ИИ). Дмитрий нажимает кнопки
  • Фазы 4-6: наращиваем мышцы — одного агента за раз
  • Фаза 7+: оптимизация, multi-brain, memory

Что делает скелет

  • 4 жёстких вопроса по очереди, кнопки выбора где можно
  • Сохранение в БД на каждом шаге (можно вернуться)
  • Глобальный /cancel и «Отмена» на любом этапе

💪 Что добавляет ИИ-мышца

  • Живые уточняющие вопросы («Расскажи подробнее про опыт с ИИ?»)
  • Анализ ответа в свободной форме (вытащить направление из текста)
  • Подбор тестового задания под профиль (а не случайно)
❓ Вопросы Дмитрию
  • Какие конкретные направления работы предлагаем выбирать? (вайбкодинг? копирайт? дизайн? SMM? аналитика? универсал?)
  • Используем ли уровни junior/middle/senior внутри направления?
  • Что делаем если кандидат вообще не работал с ИИ? Сразу отказ или даём шанс?
Этап 6 из 12 — Главное архитектурное решение

Распределение задач: кнопки vs реакции в чате

Наша позиция: уходим от «реакции в общем чате», переходим на адресную рассылку с кнопкой «Принять».

flowchart TB Task[📋 Новая задача готова] Task --> Choice{Как распределяем} Choice -->|❌ В документах| ChatPost[Пост в общий чат
«кто первый отреагировал — взял»] Choice -->|✅ Наше предложение| Smart[ИИ выбирает лучшего ассистента
под задачу + загрузка + рейтинг] Smart --> Push[Бот шлёт в ЛИЧКУ
с кнопками Принять / Отказ] Push --> Answer{Ответ за N мин} Answer -->|Принял| Work[🔨 В работе] Answer -->|Отказ / молчит| Next[Следующий ассистент по очереди] Next --> Push classDef bad fill:#3a1a1a,stroke:#ff6b6b,stroke-width:2px,color:#ff6b6b classDef good fill:#1a3320,stroke:#82c91e,stroke-width:2px,color:#82c91e class ChatPost bad class Smart,Push good

Почему кнопки лучше

  • ✅ Балансировка нагрузки — не «кто первый успел», а кто свободен и подходит
  • ✅ ИИ выбирает лучшего по рейтингу и направлению
  • ✅ Audit trail — кто отказался, кому переходило
  • ✅ Не зависит от того кто залип в чате
  • ✅ Кандидаты низкого уровня не утаскивают задачи высокого
❓ Главный вопрос Дмитрию
  • Согласен на этот подход? В документах «реакция в чате» — но это для масштаба до 5-10 ассистентов
  • По какому критерию выбирать первого? (FIFO по графику? Лучший рейтинг? Случайно? ИИ-выбор?)
  • Сколько секунд ждать ответ на «Принять/Отказаться»?
  • Что если все отказались? Эскалация Дмитрию?
  • Общий чат оставляем для анонсов (без распределения), или совсем убираем?

  • Этап 8: Выполнение задачи — лимит, дедлайн, пауза
  • Этап 9: Сдача — 4 документа (чистовик + ошибки + подсказка + ТЗ)
  • Этап 10: Ревью с умышленными ошибками — детальная процедура
  • Этап 11: Спор → судья (третий ассистент)
  • Этап 12: Оплата + еженедельный пересмотр ставки
