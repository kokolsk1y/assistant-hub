# Assistant Hub

## What It Is

Платформа-координатор, которая постепенно заменяет ручную работу менеджера-партнёра (Дмитрия) по сопровождению команды ассистентов-вайбкодеров. Покрывает путь от первого отклика на HR-воронку до завершения оплачиваемой задачи. Точка входа для пользователей — Telegram. Мозги — OpenClaw + multi-agent OpenRouter. Память — Neon Postgres. Со временем — SaaS.

## The Problem

Сейчас Дмитрий вручную делает:

- Фильтрует отклики из HR-воронки (TG-паблики + hh.ru)
- Скидывает кандидату презентацию и ждёт реакции
- Выдаёт тестовое задание под направление
- Лично оценивает результат
- Помнит кто что умеет, кто свободен, кто на каком уровне
- Считает часы по каждому ассистенту, ставит дедлайны
- Принимает работу, сверяется с ТЗ, разбирается с косяками
- Координирует выплаты

С ростом команды это упирается в одного человека. Кандидаты теряются, дедлайны забываются, нет единой памяти про ассистентов, ИИ-агенты без структурированной памяти галлюцинируют. **Без системы рост невозможен.**

## Target Users

- **Новичок (кандидат)** — пришёл из hh.ru или TG-паблика по отклику. Знает мало, ждёт быстрый ответ и понятный процесс. Уйдёт если онбординг кривой.
- **Подтверждённый ассистент** — уже прошёл онбординг. Берёт реальные задачи, отчитывается, проверяет работу других. Хочет: чёткое ТЗ, прозрачную почасовую оплату (200₽/час старт, 300₽+ с ростом рейтинга), рост.
- **Менеджер (Дмитрий)** — партнёр. Хочет: меньше ручной работы, не упускать кандидатов, видеть кто свободен/хорош, получать данные для выплат (карта + часы + сумма). Выплаты делает **сам** — мы только агрегируем. Зона Дмитрия также: общение с заказчиками и приём заказов.
- **Илья + (возможный) тех-помощник** — операторы платформы. Помощник = опционально, проектируем с возможностью второго оператора, но не блокируемся на этом.
- **Коммуникатор** — конкретный известный человек, проводит созвоны с новичками, мотивирует. Получает уведомления от бота в личку TG когда нужно действовать.

## Success Criteria (v1)

v1 = **полный онбординг-пайплайн (пп.1-5 из брифа)**, без работы с реальными оплачиваемыми задачами и без сбора финансовых реквизитов.

- Новичок попадает в TG-бот по QR/ссылке из презентации
- Проходит короткую анкету (направление, уровень, опыт с ИИ)
- Получает тестовое задание из **нашей собственной библиотеки** (см. ниже), под направление и уровень
- Сдаёт результат в бота
- ИИ-агент оценивает по нашей рубрике: **не качество кода, а качество работы с ИИ** (формулировка промптов, критичность к ответам ИИ, глубина погружения, докрутка). Возвращает балл + структурированный JSON-отчёт.
- **Мягкий дедлайн на сдачу тестового**: после выдачи задания запускаются напоминания — через 24ч / 48ч / 72ч. После 72ч кандидат помечается как «отвалился» (НЕ финальный отказ), его можно реактивировать
- Решение «годен / спорный → созвон / отказ» — **рекомендация для Дмитрия**, не финальный отказ (по ТК РФ ст. 86 нельзя автоматически отказывать на основании только автоматизированной обработки)
- Все данные новичка + балл + история сохраняются в Neon (анкета, тест, оценка, статус). **Реквизиты карты — НЕ собираем в v1.** Сбор реквизитов = отдельный флоу v2, когда подходит первая ЗП (по понедельникам).
- Коммуникатор получает в личку TG сводку по новичкам которым нужен созвон
- Дмитрий получает дайджест прошедших тест (контакт + балл + анкета, БЕЗ финансов)

**Библиотека тестовых задач — наша работа (Илья + Claude в этом проекте).** Задачи спроектированы под проверку умения работать с ИИ: в задании прямо разрешено и поощряется использование ИИ. Цель оценки — отличить «выполнил только ИИ без понимания» от «человек+ИИ, осмысленный вайбкодинг».

**Дашборд для контроля и аналитики (через TG-команды):** Дмитрий и коммуникатор могут запросить у бота сводку — кто на каком этапе воронки, сколько новичков прошло/отвалилось за период, фильтры по направлениям/уровням. В v1 — только онбординг-воронка. В v2 расширим до задач, команд, дедлайнов. Веб-дашборд — v3.

## Hard Constraints

- **Стек: OpenClaw + Neon Postgres + OpenRouter + Telegram Bot API.** Без n8n (платный). Без своих ML-моделей.
- **OpenClaw НЕ запускался ранее на этом ПК** — операционный риск, нужна отдельная фаза «boot OpenClaw → hello world в TG».
- **Хостинг: локально на ПК Ильи** на этапе MVP. Продакшн → отдельная фаза, через VPS.
- **Язык интерфейса — только русский.** Все сообщения бота, тестовые задания, отчёты, дашборды.
- **Multi-brain архитектура**: каждый ИИ-агент решает узкую задачу и отчитывается другому в строгом JSON-формате со схемой. Цель — избежать галлюцинаций и кросс-агентных ошибок коммуникации.
- **Скелет сначала, ИИ потом.** Deterministic-логика (БД, состояния FSM, обработка команд, маршрутизация в TG) должна работать без ИИ. ИИ — слой улучшения поверх работающего скелета.
- **Модели OpenRouter — хорошие** (Claude Sonnet 4.6 / Opus 4.7 для оценки и сложных решений; Haiku 4.5 — для маршрутизации/коротких задач ради бюджета). Окончательный выбор — после пробных прогонов.
- **Не лезем в выплаты, налоги, чеки, приём заказов.** Это всё — зона Дмитрия.
- **Декомпозиция задач разработки: 2-4 часа на задачу.** Каждая отдельно согласовывается с Ильёй перед началом, оплачивается отдельно.
- **Команда:** Илья (основной разработчик), возможный тех-помощник, коммуникатор-человек (не пишет код).
- **Все внешние доступы пока отсутствуют:** HR-воронка, презентация, алгоритм оценки от Дмитрия, OpenRouter ключ, Neon база, TG bot token(ы). Собираем ACCESS_REQUESTS.md и **ждём пока Дмитрий пришлёт что обещал**, не торопим.

## Known Unknowns

- Как именно работает текущая HR-воронка (стек, владелец, как достать отклики) — ждём от Дмитрия
- Где лежит презентация и можно ли её редактировать (добавить QR/ссылку в финал)
- Формальный документ с алгоритмом оценки тестов (рубрики, баллы, веса) — ждём от Дмитрия
- Готовые шаблоны тестовых заданий по направлениям — ждём от Дмитрия или придумываем сами
- Полный список направлений работы — пока известно: вайбкодинг как основное; другие — обсудим
- Точные FSM-состояния и переходы кандидата (откуда → куда → по какому событию)
- Как коммуникатор подключён к системе (тот же TG-бот или отдельный канал/группа)
- Где жить продакшн (тип VPS, домен, бюджет) — открытый вопрос
- Реальные показатели OpenClaw на русском (Whisper, Subagents, latency) — тестировать эмпирически
- Качество разных моделей OpenRouter для оценки тестов — тестировать на реальных данных

## Out of Scope (v1)

- Работа с реальными оплачиваемыми задачами (пп.6-8 из брифа) — это v2
- Самоконтроль (другой ассистент проверяет работу первого) — v2
- Почасовой учёт времени, дедлайны, авто-напоминания о сроках — v2
- **Сбор реквизитов карты ассистента** — v2, отдельный флоу при первой ЗП (по понедельникам)
- ИИ-генерация уникальных тестовых заданий — v1.5 (в v1 — наша собственная библиотека)
- Веб-UI / дашборд / SaaS-портал — v3
- Мобильное приложение — никогда (TG достаточно)
- **Приём заказов от клиентов / общение с заказчиками** — никогда наша зона, это Дмитрий
- Расчёт налогов, оформление самозанятых, выдача чеков — **никогда не наша зона**, Дмитрий сам
- Голосовые сообщения, TTS-ответы бота, видео-кружочки — v3+
- Анти-фрод (защита от ботов, дублей резюме, накруток) — v2 если станет проблемой
