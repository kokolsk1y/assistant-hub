## Что это за проект

Telegram-платформа для координации команды ассистентов-вайбкодеров. Подробно — в [PROJECT.md](PROJECT.md).

**Стек MVP:** Python 3.12+ / aiogram 3 / Neon Postgres (asyncpg) / APScheduler.
**Стек после MVP:** + OpenRouter (Claude API) / OpenClaw / Vercel.

## Жёсткие правила репо

### Что НИКОГДА не коммитим

- `.env` и любые варианты (`.env.local`, `.env.production` и т.д.) — только `.env.example`.
- Любые ключи: OpenRouter, Telegram bot token, Neon connection string, GitHub PAT.
- Файлы с `*credential*`, `*secret*`, `*token*`, `*.key`, `*.pem` в имени.
- Любые локальные документы пользователей: `*.docx`, `*.pdf`, `*.xlsx`, `*.zip`.
- Папки `dmitry-docs/`, `managers-docs/`, `private/`, `hr-tasks/`, `notes_local/`.
- Локальное состояние Claude Code: `.claude/`, `.gsd/`.

Если есть сомнения — **не коммить, спроси Колю**.

### Перед каждым commit

1. Запусти `git status` и убедись что в stage нет:
   - файлов с подозрительными именами (содержат слова из списка выше)
   - офисных документов (`.docx` и т.д.)
   - чужих папок (`dmitry-docs/`, `hr-tasks/` и т.п.)
2. Если случайно зарегистрировал — `git restore --staged <file>` до коммита.
3. Если уже закоммитил секрет — **не пуш**, делай `git reset HEAD~1` и фикси.

### Force-push

- На master/main — только с явного разрешения Коли.
- На свои feature-ветки — можно свободно.

## Архитектурные принципы (соблюдать строго)

### 1. Скелет сначала, ИИ потом

- В MVP **никакого LLM-вызова в проде**. Дмитрий/Александр сами нажимают кнопки оценки.
- ИИ подключаем в фазе D1 (ИИ-оценщик) и далее. До этого — детерминированная логика.

### 2. Все бизнес-правила в Neon

**Никогда не хардкодим в коде:**
- Грейды и ставки (Junior/Middle/Senior)
- Типы ошибок и их последствия
- Коэффициенты доработки (1.0 / 0.8 / transfer)
- Окно тендера (5–10 мин)
- Grace-период дедлайна (2ч)
- Лимит fails per month (3)
- Чек-лист peer-review
- Триггеры запуска фаз D/R

**Всё это лежит в таблицах `grades`, `error_types`, `retry_policies`, `config`** в Neon. Код читает через тонкий модуль `src/policies/`.

**Зачем:** когда подключатся ИИ-агенты в Доработке/Развитии, они читают тот же источник что и код. Без рассинхрона.

### 3. Декомпозиция

- Максимум 8 часов на фазу. Каждая фаза самостоятельная.
- Если задача больше — разбивай на под-фазы.

### 4. Только русский

Все сообщения бота, тестовые задания, отчёты, документация — на русском. Имена переменных/функций/таблиц — английские.

### 5. Multi-brain в Развитии II

Когда дойдём до R3 — каждый ИИ-агент решает узкую задачу и отвечает в JSON-схеме. Без «универсального ассистента».

## Конвенции кода

### Python

- Python 3.12+
- Async везде где можно (`async def`, `await`)
- `asyncpg` для Postgres (НЕ SQLAlchemy в MVP)
- aiogram 3 (НЕ aiogram 2, синтаксис другой)
- Типизация обязательна (`from __future__ import annotations`)
- Никаких блокирующих вызовов в async-функциях (`time.sleep` → `asyncio.sleep`)

### Имена

- Таблицы БД: `snake_case`, множественное число (`candidates`, `tasks`, `task_assignments`)
- Поля БД: `snake_case` (`created_at`, `tg_id`, `expected_result`)
- Python-функции: `snake_case`
- Классы: `PascalCase`
- Константы: `UPPER_CASE`
- Переменные TG-команд: с `/` (`/start`, `/queue`, `/newtask`)

### Коммиты

Формат conventional:
```
тип(скоуп): краткое описание

Подробности при необходимости.

Co-Authored-By: Claude Opus 4.7 (1M context) <noreply@anthropic.com>
```

Типы: `feat`, `fix`, `docs`, `refactor`, `test`, `chore`.

Скоупы: `db`, `bot`, `policies`, `jobs`, `m1`-`m14` (для конкретных фаз), `docs`.

Примеры:
- `feat(m1): WSL2 + Python + aiogram 3 setup`
- `feat(db): таблицы grades, error_types, retry_policies + seed`
- `fix(bot): /cancel сохраняет введённые данные`

## Workflow с Claude Code

### При старте сессии в этом проекте

1. Прочитай `PROJECT.md` — концепция и текущие правила.
2. Прочитай `docs/IMPLEMENTATION_PLAN.md` — где мы в плане сейчас.
3. Глянь `tasks.json` — раздели задачи: согласованные (`approved: true`) и на рассмотрение.
4. Глянь последние коммиты — что только что делали.

### При работе

- Если правишь бизнес-правила (грейды, типы ошибок и т.п.) — **сначала** меняй в `PROJECT.md` (для людей) и сразу же — миграцию в Neon (для кода и ИИ). Не разводи руки.
- Если добавляешь новую фазу/задачу — обнови `docs/IMPLEMENTATION_PLAN.md` и `tasks.json`.
- Перед `git push` — проверь `git status` на чувствительные файлы (см. выше).

### Никогда

- Не запускай `git push --force` на master/main без явного разрешения.
- Не коммить `.env`, `.claude/`, `.gsd/`, любые `*.docx`/`*.pdf` пользователя.
- Не подсовывай LLM-вызовы в MVP-код (это для D1+).
- Не хардкодь числа из бизнес-правил — читай из `policies`.
- Не создавай файлы-копии (`_v2`, `_old`, `_backup`) — правь оригинал.
