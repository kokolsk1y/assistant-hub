# План реализации Assistant Hub

> **Подход:** MVP включает всё что нужно для работы качественной платформы (правильный ПДн-flow, ACL ролей, напоминания, документация). Тяжёлый ИИ-обвес и взаимопроверка — поэтапные доработки.
>
> **Все цифры с буфером ~30%** на отладку и сюрпризы.

---

## 📊 Общая структура

```
🎯 MVP                          35-45 часов      2 недели по вечерам
   └─ полностью работающая платформа с грамотной механикой

🔧 ДОРАБОТКА I                  30-40 часов
   └─ ИИ-агенты, личный кабинет, шаблоны

🚀 РАЗВИТИЕ II                  50-70 часов
   └─ взаимопроверка, Manager Hub, прод-VPS
```

**Итого до полной системы:** 115-155 часов на 3-4 месяца постепенно.

---

# 🎯 MVP (35-45 часов)

**Цель:** Запустить **качественную платформу** где можно реально работать с командой. Без ИИ-оценщика (Дмитрий сам нажимает кнопки), без взаимопроверки. Но с правильным ПДн-flow, ACL, напоминаниями, документацией — то что критично с первого дня.

---

## Фаза M1: Инфраструктура (4-5ч)

| Задача | Критерий приёмки | Лимит |
|--------|-----------------|-------|
| M1.1 WSL2 + Python 3.12+ + aiogram 3 | Все установлено, тест-импорты работают | 1.5ч |
| M1.2 Neon Postgres подключение | asyncpg соединяется, тест-запись/чтение | 1ч |
| M1.3 TG-бот через @BotFather (dev токен) | `/start` возвращает «привет» | 1ч |
| M1.4 Структура проекта + `.env.example` + `.gitignore` | 4 модуля (config, db, bot, handlers), коммит | 1.5ч |

---

## Фаза M2: Схема БД + миграции (4-5ч)

| Задача | Критерий приёмки | Лимит |
|--------|-----------------|-------|
| M2.1 Таблица `candidates` (FSM + анкета + источник) | Создана с полями: tg_id, fsm_state, fsm_data, name, direction, level, ai_exp, source, pdn_consent_at, created_at, updated_at | 1.5ч |
| M2.2 Таблица `tests` (библиотека заданий) | id, title, text, criteria, direction, level, time_limit_minutes | 0.5ч |
| M2.3 Таблица `test_submissions` (сданные работы) | candidate_id, test_id, submission, started_at, submitted_at, status, reviewer_decision, reviewer_comment | 1ч |
| M2.4 Таблица `tasks` (реальные задачи) + `task_assignments` | tasks: text, criteria, time_limit, deadline, status. assignments: task_id, assistant_id, status, accepted_at, hours_spent | 1.5ч |
| M2.5 Таблица `audit_log` + `operators` (ACL) | audit: action, actor, payload, ts. operators: tg_id, role | 0.5ч |

---

## Фаза M3: ПДн-flow + анкета (7-9ч)

| Задача | Критерий приёмки | Лимит |
|--------|-----------------|-------|
| M3.1 Первое сообщение с **корректным согласием на ПДн** | Inline-кнопка «Согласен на обработку», timestamp в БД, без согласия дальше нет | 1.5ч |
| M3.2 Парсинг source-метки из deeplink `?start=src_X` | Метка сохраняется в `candidates.source` | 1ч |
| M3.3 FSM анкеты на 4 вопроса с кнопками | Имя/направление/уровень/опыт. Состояние в БД, переживает рестарт бота | 3.5ч |
| M3.4 Глобальные команды `/cancel`, `/me`, `/help` | Работают в любом состоянии. `/cancel` сбрасывает без потери введённых данных (для возможной реактивации) | 1.5ч |
| M3.5 **Реактивация прерванной анкеты** | Если /start повторно — бот предлагает «продолжить с того места» или начать заново | 1.5ч |

## Фаза M4: Тестовое задание (5-6ч)

| Задача | Критерий приёмки | Лимит |
|--------|-----------------|-------|
| M4.1 Одно отборочное задание в БД + выдача | Сразу после анкеты — текст задания, критерии, лимит | 1ч |
| M4.2 Приём результата (текст/файл/ссылка) | 3 типа сохраняются в `test_submissions` | 2ч |
| M4.3 **Мягкие напоминания через APScheduler** | Через 24/48/72ч — напоминания. На 72ч помечается «отвалился» (но не отказ) | 2.5ч |
| M4.4 Уведомление кандидату о приёме на оценку | «Принято, решение через X» | 0.5ч |

---

## Фаза M5: Дашборд оценки для модератора (6-7ч)

| Задача | Критерий приёмки | Лимит |
|--------|-----------------|-------|
| M5.1 **Полноценный ACL** через таблицу `operators` | Команды модератора (`/queue`, `/newtask`, `/weekly`) недоступны кандидатам. Декоратор `@require_role` | 1.5ч |
| M5.2 Команда `/queue` со списком сданных | Карточки: имя/направление/балл/ссылка/время сдачи. Фильтр по статусу | 2ч |
| M5.3 Кнопки решения «принять / на созвон / отказ» | Меняет статус кандидата, шлёт уведомление | 1.5ч |
| M5.4 **Поле для комментария Дмитрия** | После решения — может ввести комментарий, он идёт в уведомление кандидату | 1.5ч |

## Фаза M6: Создание и распределение задач (6-7ч)

| Задача | Критерий приёмки | Лимит |
|--------|-----------------|-------|

| M6.3 Адресная рассылка с кнопками «Принять/Отказ» + таймаут | Если не ответил за N мин — переход к следующему | 2ч |
| M6.4 Учёт фактического времени (start/pause/end) | Команды `/start_work`, `/pause`, `/done`. Часы записываются в БД | 1.5ч |

## Что важно проговорить Дмитрию

1. **MVP — это не «прототип» а полноценная платформа.** Просто без ИИ-обвеса который не критичен с первого дня.
2. **Цифры с буфером** на отладку (~30%). Реалистичные, не оптимистичные.
3. **Доработки и Развитие — НЕ обязательны разом.** Берём по факту что болит.
4. **Можно остановиться на любом этапе.**
5. **Темп подстраивается** под Колю (экзамены, основная работа).
6. **Оплата по этапам** — после каждой большой фазы, не предоплата.
