# План реализации Assistant Hub

> **Подход для стартапа с ограниченным бюджетом:**
> Минимум-минимума что реально работает → проверяем на людях → дорабатываем только то что нужно по фактам.
>
> **Все цифры уже включают буфер на отладку и неожиданности.** Это не оптимистичная оценка — это реалистичная.

---

## 📊 Общая структура

```
🎯 MVP-МИНИМУМ                  21-28 часов     1.5-2 недели по вечерам
   └─ работает с реальными кандидатами и задачами

🔧 ДОРАБОТКА I (по запросу)       15-25 часов
   └─ только то что реально нужно после первого месяца

🚀 РАЗВИТИЕ II (когда вырастет)   25-40 часов
   └─ только если объём команды требует
```

**Итого до полной системы:** 60-95 часов. Но **первая работающая версия — 21-28 часов**.

---

# 🎯 MVP-МИНИМУМ (21-28 часов)

**Что входит:** базовая механика онбординга кандидата + работы с задачами. Без ИИ. Без сложных автоматизаций. Дмитрий сам нажимает все кнопки оценки.

**Что НЕ входит** (это уже не MVP, см. ниже): ИИ-оценщик, взаимопроверка, личный кабинет, метрики, шаблоны, VPS-деплой, Manager Hub.

---

## Фаза M1: Инфраструктура (3-4ч)

**Цель:** Бот существует, отвечает на `/start`, может писать в БД.

| Задача | Критерий | Лимит (с буфером) |
|--------|----------|------|
| M1.1 Python + aiogram + Neon | `python` работает в WSL2, `aiogram` поставлен, `psycopg` соединяется с Neon | 1ч |
| M1.2 TG-бот через BotFather | Токен в `.env`, `/start` возвращает «привет» | 0.5ч |
| M1.3 Структура проекта + миграция базы | 1 таблица `candidates` создана, бот пишет туда тестовую запись | 1.5ч |
| M1.4 Буфер | На сюрпризы установки | 1ч |

---

## Фаза M2: Анкета новичка (4-6ч)

**Цель:** Кандидат заходит по ссылке, видит согласие на ПДн (текстом), отвечает на 4 вопроса, его данные в БД.

| Задача | Критерий | Лимит |
|--------|----------|------|
| M2.1 Первое сообщение с согласием | Текст с предупреждением о ПДн + кнопка «Продолжить». Timestamp сохраняется | 1ч |
| M2.2 FSM на 4 вопроса с кнопками | Имя/направление/уровень/опыт с ИИ. Проходится за < 2 мин | 3ч |
| M2.3 Команда `/cancel` | Сбрасывает state, можно начать заново | 0.5ч |
| M2.4 Буфер | Отладка FSM-переходов | 1.5ч |

---

## Фаза M3: Тестовое задание (3-5ч)

**Цель:** Кандидат получает одну отборочную задачу, выполняет, сдаёт результат.

| Задача | Критерий | Лимит |
|--------|----------|------|
| M3.1 Одно задание в БД + выдача | Текст задания приходит в чат сразу после анкеты | 1ч |
| M3.2 Приём результата (текст/файл/ссылка) | Любой тип сохраняется в `submissions` со статусом «ждёт оценки» | 2ч |
| M3.3 Уведомление «Принято, ждите решения» | Кандидат видит ответ + дату когда ждать | 0.5ч |
| M3.4 Буфер | На обработку разных форматов файлов | 1.5ч |

---

## Фаза M4: Дашборд оценки (4-5ч)

**Цель:** Дмитрий через бота видит сданные работы и принимает решения кнопками.

> Без сложного ACL: hardcoded `chat_id` Дмитрия и Коли как операторов в config.

| Задача | Критерий | Лимит |
|--------|----------|------|
| M4.1 Команда `/queue` | Список ожидающих с краткими карточками | 1.5ч |
| M4.2 Кнопки решения | «принять / на созвон / отказ» → статус меняется, кандидату уведомление | 2ч |
| M4.3 Буфер | Отладка callback-handlers | 1.5ч |

---

## Фаза M5: Работа с задачами (4-6ч)

**Цель:** Дмитрий создаёт реальную задачу через бот, бот шлёт её свободному ассистенту с кнопкой «Принять», учёт часов.

| Задача | Критерий | Лимит |
|--------|----------|------|
| M5.1 Команда `/newtask` | Дмитрий вводит текст/лимит/дедлайн, запись в БД | 1.5ч |
| M5.2 Простое назначение | Первый свободный активный ассистент. Кнопки «Принять/Отказ». Если отказ — следующий | 2ч |
| M5.3 Учёт часов | Когда ассистент сдал — спрашиваем «сколько часов потратил» | 1ч |
| M5.4 Буфер | Edge-cases распределения | 1.5ч |

---

## Фаза M6: Сводка для выплат (1-2ч)

**Цель:** Команда `/weekly` для Дмитрия возвращает таблицу для выплат.

| Задача | Критерий | Лимит |
|--------|----------|------|
| M6.1 Команда `/weekly` | Таблица: ассистент / задач / часов / сумма за неделю | 1.5ч |

---

## Фаза M7: Тест и запуск (2-3ч)

**Цель:** Прогон полного цикла на тестовом аккаунте. Готовы принять первого реального кандидата.

| Задача | Критерий | Лимит |
|--------|----------|------|
| M7.1 End-to-end на тестовом | Один прогон без багов: /start → анкета → тест → решение → задача → оплата | 1.5ч |
| M7.2 Краткая инструкция Дмитрию | 1 страница «Как пользоваться ботом» | 1ч |

## 🎯 Что MVP даёт после запуска

# 🔧 ДОРАБОТКА I — только то что реально болит (15-25ч)

После месяца работы становится понятно что нужно. Возможные доработки в порядке вероятной важности:

| # | Что | Часов | Когда нужно |
|---|-----|-------|------------|
| D1 | ИИ-оценщик (если Дмитрий устал оценивать вручную) | 8-12 | Если кандидатов >5/неделя |
| D2 | Личный кабинет ассистента `/me` | 3-5 | Если просят сами ассистенты |
| D3 | Шаблоны сообщений (созвон, замечание) | 2-4 | Если Дмитрий пишет одинаковое часто |
| D4 | Автопересмотр ставки | 2-4 | Если еженедельный пересмотр стал рутиной |

**Берём только то что реально болит, не всё подряд.**

При 300₽/час: **4 500 – 7 500 ₽** за реальные нужды.

## ⚠️ Что важно проговорить Дмитрию

1. **Цифры уже с буфером** на отладку, edge-cases, переотделки. Не «оптимистичная оценка которую раздуем потом» — это **реалистичная цена**.
2. **MVP не значит «прототип»** — это работающая система, в которой можно вести реальную команду. Просто без ИИ-обвеса.
3. **Доработки и Развитие — НЕ обязательны.** Если MVP закрывает потребности — на нём и остаёмся.
4. **Темп подстраивается под Колю** (экзамены, основная работа). 1.5-2 недели — комфортный, не «горящий».

- Дедлайн

Можно согласовать пакет 3-5 задач за раз.

## ⚠️ Главные риски (с митигациями)

| Риск | Что делаем |
|------|-----------|
| OpenClaw на Windows не работает | В MVP его НЕТ. Прямые вызовы API |
| Дмитрий не успевает с материалами | M1-M4 не требуют его материалов. Делаем без них |
| Экзамены давят на темп | План растягивается до 3 недель вечерами без удорожания |
| Сложности с какой-то фазой | Буфер ~30% уже встроен в каждую цифру |
