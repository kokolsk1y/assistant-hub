# План реализации Assistant Hub

> **Подход:** сначала минимально жизнеспособный MVP (можно запускать и проверять на реальных людях), потом — поэтапные доработки по обратной связи.

---

## 📊 Общая структура

```
🎯 MVP МИНИМУМ                     ~30-50 часов     2 недели по вечерам
   └─ запускается и работает с реальными кандидатами и задачами

🔧 ДОРАБОТКИ I (после первого месяца)  ~30-50 часов
   └─ ИИ автоматизация, взаимопроверка, метрики

🚀 РАЗВИТИЕ II (через 2-3 месяца)      ~30-50 часов
   └─ Manager Hub, дашборды, прод-VPS, multi-brain
```

**Итого до полной системы:** 90-150 часов, но **первая работающая версия — 30-50 часов**.

---

# 🎯 MVP МИНИМУМ (30-50 часов)

**Цель:** Запустить рабочую механику онбординга и базовой работы с задачами **без ИИ-агентов**. Дмитрий сам оценивает кандидатов и принимает работы через кнопки в боте. Это и есть «скелет» из принципа архитектуры.

После MVP мы видим **реальный поток**: сколько кандидатов, какие проблемы, что нужно улучшить. Дальнейшие доработки делаем уже по фактам, не по предположениям.

---

## Фаза M1: Старт инфраструктуры

**Цель:** Все компоненты установлены, бот отвечает на `/start`.

| Задача | Критерий приёмки | Лимит |
|--------|-----------------|-------|
| M1.1 — WSL2 + Python aiogram 3 | `python -V` показывает 3.12+, `aiogram` устанавливается без ошибок | 1.5ч |
| M1.2 — Создать Neon базу `assistant_hub` | Подключение из Python через asyncpg работает, тестовая запись/чтение проходит | 1ч |
| M1.3 — Создать TG-бот через @BotFather | Бот существует, токен в `.env`, `/start` возвращает «Привет» | 1ч |
| M1.4 — Структура проекта (config, db, bot) | 4 модуля созданы, импорты работают, `.env.example` зафиксирован | 1ч |

**Итого фаза M1:** 4-5 часов

---

## Фаза M2: Минимальная анкета новичка

**Цель:** Новичок проходит онбординг — соглашается с ПДн, отвечает на 4 вопроса, его данные в БД.

| Задача | Критерий приёмки | Лимит |
|--------|-----------------|-------|
| M2.1 — Таблица `candidates` + миграция | Таблица создана с полями: tg_id, fsm_state, name, direction, level, ai_exp, pdn_consent_at, source, created_at | 1ч |
| M2.2 — Согласие на ПДн (ФЗ-152) | Первое сообщение бота — кнопка «Согласен». Без согласия дальше не идём. Timestamp в БД | 1.5ч |
| M2.3 — FSM анкеты на 4 вопроса с кнопками | Анкета проходится от начала до конца за < 2 минут. Состояние переживает рестарт бота | 4ч |
| M2.4 — Команда `/cancel` и обработка отказа | Работает в любом состоянии, сбрасывает state без потери уже введённых данных | 1ч |

**Итого фаза M2:** 7-8 часов

---

## Фаза M3: Тестовое задание + сдача

**Цель:** Кандидат получает одно отборочное задание, выполняет, сдаёт результат в бота.

| Задача | Критерий приёмки | Лимит |
|--------|-----------------|-------|
| M3.1 — Таблица `tests` + одно отборочное задание | В БД лежит одно отборочное задание (текст + критерий приёмки + лимит) | 1ч |
| M3.2 — Выдача задания после анкеты | Бот выдаёт задание в чат + запускает таймер на 48ч с одним напоминанием через 24ч | 2ч |
| M3.3 — Приём результата (текст / файл / ссылка) | 3 типа сдачи сохраняются в `test_submissions` | 2ч |
| M3.4 — Статус «ждёт оценки» + уведомление | Кандидат видит «Принято, ждите решения», запись в БД с timestamp | 1ч |

**Итого фаза M3:** 6-7 часов

---

## Фаза M4: Дашборд оценки для Дмитрия

**Цель:** Дмитрий через бота видит очередь сданных работ и принимает решения кнопками.

| Задача | Критерий приёмки | Лимит |
|--------|-----------------|-------|
| M4.1 — ACL ролей (modulator / candidate) | Таблица `operators` с role. Команды модератора недоступны кандидатам | 1.5ч |
| M4.2 — Команда `/queue` со списком сданных | Дмитрий видит список с краткими карточками: имя, направление, ссылка на результат | 2ч |
| M4.3 — Кнопки «принять / на созвон / отказ» | Нажатие → статус кандидата меняется, уведомление в личку кандидату | 2ч |
| M4.4 — Поле для комментария Дмитрия | После решения — может ввести короткий комментарий, который идёт в уведомление кандидату | 1ч |

**Итого фаза M4:** 6-7 часов

---

## Фаза M5: Минимальная работа с задачами

**Цель:** Дмитрий создаёт реальную задачу через бота, бот шлёт её свободному ассистенту с кнопкой «Принять».

| Задача | Критерий приёмки | Лимит |
|--------|-----------------|-------|
| M5.1 — Таблица `tasks` + команда `/newtask` | Дмитрий вводит: текст задачи, лимит, дедлайн. Запись в БД со статусом «open» | 2ч |
| M5.2 — Простой алгоритм выбора ассистента | Выбирается первый свободный активный ассистент (round-robin). Не сам автор задачи | 1.5ч |
| M5.3 — Адресная рассылка с кнопкой «Принять» | Ассистент получает в личке: задание + кнопки «Принять / Отказ». Если отказался — следующий | 2ч |
| M5.4 — Учёт часов (start / stop / done) | Когда ассистент сдал — бот спрашивает «сколько часов потратил». Записывает в БД | 1.5ч |

**Итого фаза M5:** 6-7 часов

---

## Фаза M6: Сводка для выплат

**Цель:** Дмитрий получает еженедельную таблицу для выплат.

| Задача | Критерий приёмки | Лимит |
|--------|-----------------|-------|
| M6.1 — Команда `/weekly` со сводкой | Возвращает таблицу: ассистент / задач / часов / сумма по ставкам. Покрывает прошлую неделю | 2ч |
| M6.2 — Cron-job еженедельной отправки в понедельник | В понедельник 09:00 — автоматическая отправка сводки Дмитрию без запроса | 1.5ч |

**Итого фаза M6:** 3-4 часа

---

## Фаза M7: Тест с первым реальным кандидатом + полировка

**Цель:** Один настоящий человек прошёл полный цикл — от QR в презентации до закрытой задачи.

| Задача | Критерий приёмки | Лимит |
|--------|-----------------|-------|
| M7.1 — End-to-end тест на тестовом аккаунте | Пройти всю воронку: /start → анкета → тестовое → решение → реальная задача → оплата. Без багов | 2ч |
| M7.2 — Документация для Дмитрия | Документ «Как работать с ботом» (1 страница). Встроенный `/help` в боте | 1.5ч |
| M7.3 — Первый реальный кандидат | Один новичок реально проходит весь цикл | по факту |

**Итого фаза M7:** 3-4 часа + время на реакцию

## 🎯 Что MVP делает / НЕ делает

### ✅ Делает (после запуска можно начинать работать)

- Принимает кандидатов через QR в презентации
- Собирает согласие на ПДн (юридически чисто)
- Прогоняет через анкету
- Выдаёт отборочное задание
- Принимает результат
- Дмитрий через бот оценивает решения кнопками
- Передаёт принятых в полноценную работу
- Принимает реальные задачи от Дмитрия
- Распределяет первому свободному ассистенту с кнопкой «Принять»
- Считает часы и формирует сводку для выплат

### ❌ Не делает в MVP (доработки)

- ИИ автоматически не оценивает тесты (это делает Дмитрий)
- Нет процедуры взаимной проверки (ревью)
- Нет автоматического пересмотра ставки
- Нет личного кабинета ассистента
- Нет умного распределения по рейтингу
- Нет шаблонов сообщений / proxy-коммуникаций
- Нет Manager Hub бота
- Нет дашбордов аналитики
- Работает локально, не на VPS

**Эти вещи добавляются после первого месяца работы по реальным потребностям.**

## ⚠️ Риски и буферы

| Риск | Митигация |
|------|-----------|
| OpenClaw не запускается на Windows | В MVP его НЕТ. Прямые вызовы API, OpenClaw — в Развитии II |
| Промпт-инженерия ИИ сложнее ожидаемого | В MVP ИИ нет. В Доработках I — Sonnet 4.6 с готовой рубрикой |
| Дмитрий не успевает прислать материалы | M1-M3 не зависят от него. Можем сделать без презентации (через `/start` напрямую) |
| Экзамены Коли давят | MVP укладывается в 35-42ч, можно растянуть на 3 недели вечерами |
| Большая фаза ревью (M5) едет | В MVP нет ревью. Появляется в Развитии II как R1 |
