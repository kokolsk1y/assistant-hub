## Дедлайн задачи: двусторонне согласование (от Коли, 2026-05-22)

**Идея:** дедлайн на задачу — не назначается одной стороной, а согласуется через бота.

**Поток:**
1. Дмитрий или система создаёт задачу с описанием и **лимитом времени** (= потолок оплаты: например 4 часа × 200₽/час = 800₽)
2. Работник видит задачу в TG, прикидывает что успеет за N часов до D-даты, **предлагает дедлайн** в боте
3. Бот формирует Дмитрию карточку: «Работник Х предложил дедлайн D для задачи Y, его оценка N часов из бюджета M»
4. Дмитрий нажимает **inline-кнопку**: ✅ согласовать / ❌ возразить
5. Если ❌ — открывается поле комментария «почему не согласен / какой дедлайн нужен»
6. Работник получает решение → если ❌, может предложить другой дедлайн (цикл, лимит 2-3 итерации)
7. Если согласовано — дедлайн фиксируется, ИИ-агент начинает следить за приближением сроков

**Связанные требования:**
- Почасовая оплата с потолком на задачу
- ИИ-напоминания о дедлайне (за 24ч, за 4ч, за 1ч до)
- История переговоров дедлайнов (сколько раз работник просил продлить, как часто Дмитрий не согласен)
- Метрика «срывы дедлайнов» в дашборде Дмитрия

**Открытые вопросы:**
- Что если работник не предложил дедлайн вообще (висит на задаче) — авто-таймаут N часов?
- Что если Дмитрий не отвечает на согласование (висит у него) — авто-эскалация Коле?
- Можно ли менять дедлайн ПОСЛЕ согласования (форс-мажор) — отдельный флоу?
- Кто инициирует задачу — Дмитрий вручную или ИИ-агент из очереди заказчиков?

## Сбор реквизитов карты (от Коли, 2026-05-22)

Не в онбординге. Только когда первая ЗП = по понедельникам.

Бот шлёт сообщение в установленном формате (Дмитрий пришлёт шаблон), собирает:
- Номер карты
- ФИО владельца
- Возможно — банк (для СБП)

Передаёт Дмитрию вместе с агрегированными часами. Дмитрий платит сам.

## Самоконтроль (взаимная проверка работ)

Из брифа п.7: задача закончилась → решение проверяет ДРУГОЙ ассистент (не ИИ) → это тоже считается работой.

**Открытые вопросы:**
- Кто платит проверяющему — Дмитрий или вычитается из оплаты автора задачи?
- Что если проверяющий не согласен — кто арбитр (Дмитрий, Коля, ИИ)?
- Сколько проверок (1 или N)?

## Дашборд v2 — расширение

В v1 — только онбординг-воронка через TG-команды. В v2 добавить:
- Задачи в работе / закрытые / просроченные
- Фильтры по команде, по направлению, по периоду
- Метрика загруженности ассистентов
- ROI по ассистенту (заработал клиенту X, обошёлся в Y)

## ИИ-генерация уникальных тестовых заданий (v1.5)

В v1 — наша библиотека шаблонов. В v1.5:
- ИИ генерирует уникальную задачу из шаблона (меняет домен/контекст)
- Это снижает риск утечки решений между кандидатами
- Требует валидации сгенерированной задачи перед выдачей (плохой шаблон → плохой кандидат)
