# 4 базовых промпта-компонента (из коробки)

> ⚠️ Эти 4 компонента — **намеренно простые**. Каждый «более-менее работает», но в каждом есть слабое место, которое начнёт сыпать, как только ты прогонишь конвейер на тренировочных кейсах. Твоя задача — найти эти места и **точечно** их починить (или подменить шаг своей версией).

Шаги связаны так:

```
input (сообщение клиента)
  ↓
[1] CLASSIFIER → category
  ↓
[2] EXTRACTOR → {topic, urgency, client_type}
  ↓
[3] CONTEXT WRAPPER → большой промпт (Анна-профиль + всё выше + сообщение)
  ↓
[4] REWRITER → черновик ответа
```

---

## [1] CLASSIFIER (классификатор)

**Что делает:** определяет, к какой из 4 категорий относится входящее сообщение клиента.

**Промпт (как есть, из коробки):**

```
Определи тип сообщения от клиента. Выбери одну из категорий:
- pricing — клиент спрашивает про цену услуги
- service_request — клиент хочет заказать услугу
- off_topic — сообщение не про IT-карьеру (миграция, инвестиции, психотерапия и т.д.)
- complaint — клиент чем-то недоволен

Ответь одним словом — название категории.

Сообщение клиента:
{message}
```

**Вход:** строка (сообщение клиента).
**Выход:** одно из 4 слов.

---

## [2] EXTRACTOR (экстрактор полей)

**Что делает:** вытаскивает три структурированных поля из сообщения.

**Промпт (как есть, из коробки):**

```
Извлеки из сообщения клиента три поля и верни JSON:
- topic: о чём конкретно сообщение (короткая строка)
- urgency: насколько срочно (низкая/средняя/высокая)
- client_type: новый клиент или уже работает с Анной (новый/постоянный)

Сообщение клиента:
{message}

Верни только JSON без комментариев.
```

**Вход:** строка (сообщение клиента).
**Выход:** JSON с тремя полями.

---

## [3] CONTEXT WRAPPER (контекст-обёртка)

**Что делает:** собирает большой промпт с профилем Анны и метаданными (классом + полями), который дальше идёт в переписчик.

**Промпт (как есть, из коробки):**

```
Ты — Анна Петрова, карьерный консультант в IT.

ПРОФИЛЬ АННЫ:
{anna_profile}

КЛАСС СООБЩЕНИЯ: {category}
ИЗВЛЕЧЁННЫЕ ПОЛЯ: {fields_json}

СООБЩЕНИЕ КЛИЕНТА:
{message}

Напиши ответ клиенту от лица Анны.
```

Где `{anna_profile}` — весь файл `anna-compact.md` целиком (около 600 слов), независимо от того, относится сообщение к её темам или нет.

**Вход:** сообщение + категория + JSON полей + профиль Анны.
**Выход:** большой промпт-инструкция для переписчика.

---

## [4] REWRITER (переписчик в тон)

**Что делает:** получает большой промпт от обёртки и пишет финальный черновик.

**Промпт (как есть, из коробки):**

```
{wrapped_prompt}

Ответь профессионально и тепло. Будь как Анна — карьерный консультант с опытом.
```

**Вход:** обёрнутый промпт от шага 3.
**Выход:** финальный текст ответа клиенту.

---

## Подсказка по поиску слабых звеньев

Не спойлерим — но если прогонишь конвейер на 4-5 тренировочных кейсах из `cases.md`, ты заметишь, что **сбои бывают разной природы**: где-то классификатор путает похожие категории, где-то экстрактор странно ведёт себя на сообщениях с неочевидными полями, где-то в шаге 3 или 4 теряются точные факты из профиля Анны, где-то страдает тон. Сколько именно слабых мест и в каких шагах — выясняй сам.

Хороший способ: для каждого тренировочного кейса прогоняй **шаги по одному** (не всё сразу) и смотри промежуточный выход. Тогда сразу видно, на каком шаге что-то «поехало».
