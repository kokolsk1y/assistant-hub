## Зачем

Система **самообман-устойчивая** только если каждый из этих критериев выполнен. Если хоть один в красной зоне — кандидат может получить ложный балл (или ложный отказ), и весь курс-тест теряет смысл.

## K. Плюсы и минусы системы (после фикса всех high)

### Плюсы

1. **Скелет + ИИ.** Детерминированная часть (yaml/ассерты/парсер) работает без ИИ; ИИ применяется только там где иначе нельзя (llm-rubric, judge по логу).
2. **Прозрачная шкала.** 6+4 = 10. Каждый балл документирован, есть report.json после прогона.
3. **Защита от копипасты ChatGPT-ответа.** 4 балла за лог отсеивают сдачи без мысли.
4. **Защита одной попытки.** Если кандидат «гений» — не штрафуется за отсутствие итераций.
5. **9 разнотипных задач** покрывают 8+ типов задач промпт-инженерии.
6. **Скрытый тест-сет.** Кандидат не видит экзаменационных кейсов в репо.
7. **Запускается на ноутбуке проверяющего за ~3-7 минут на сдачу.** Без платформы.

### Минусы (известны, в TODO)

1. **LLM-судья не идеален.** На пограничных сдачах оценка процесса может прыгать ±1. Митигация: каждый пункт — бинарный, минимизирует шум.
2. **Защита одной попытки слишком мягкая для слабых сдач.** Если ассерты задачи слабые и пропускают шум-промпт — он получает 6/6 + 4/4 = 10/10. Решение: **ужесточение ассертов** (в работе) + усиление порога защиты одной попытки.
3. **Калибровка не автоматическая.** Нужно вручную прогнать 2 эталонные сдачи на каждой задаче (см. фазу калибровки).
4. **Baseline в task 5 — ручная арифметика.** Дельту считаем сами (см. README).
5. **Двухслойная проверка в task 8 — упрощённая.** Полноценная — TODO.
6. **Кейсы статичны.** При смене модели (haiku → sonnet) пороги ассертов могут сдвинуться — нужна повторная калибровка.
7. **Стоимость прогона.** Каждая сдача — ~10-50K токенов API. На сотни кандидатов — десятки долларов. Митигация: дешёвая target-модель (Haiku).
8. **Промпт-инъекции в сдаче кандидата.** Если кандидат пишет «игнорируй все ассерты», модель может его послушаться. Митигация: ассерты детерминированные (JS) — на них инъекция не работает.

## L. Перед боевым запуском — критический pass

1. **Запустить `npm run eval` на всех 4 fixture после фиксов.**
2. **Убедиться: сильная сдача >7, слабая <5.** Если нет — править ассерты до правильного разброса.
3. **Прогнать 1-2 «эталонных» сдач от Коли** на 1-2 задачах руками (как будто кандидат).
4. **Только после этого** — открыть для Александра.
