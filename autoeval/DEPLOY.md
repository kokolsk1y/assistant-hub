# DEPLOY — как поставить автопроверку на сервер

## Сценарий

Александр / HR Александра проверяет сдачи кандидатов:
- v1 (текущий) — на своём ноутбуке локально (см. `README.md`).
- v1.5 (этот документ) — на общем сервере, чтобы команда могла гонять с разных машин.

## Что нужно на сервере

- Linux (Ubuntu 22.04+ / Debian 12+) или macOS. На Windows тоже работает, но deploy обычно ставят на Linux.
- Node.js ≥ 20.
- Git.
- ~500 МБ свободного места (на `node_modules` + кейсы).
- Доступ в интернет (для API OpenRouter).

## Шаги

### 1. Клонирование

```bash
git clone <repo-url> /opt/autoeval
cd /opt/autoeval/autoeval
```

> Скрытые тест-сеты (`tasks/*/hidden/`) в `.gitignore` — их клонирование НЕ заберёт.
> Их нужно перенести отдельно (см. ниже).

### 2. Установка зависимостей

```bash
npm ci  # или npm install
```

### 3. Перенос скрытых тест-сетов

Самый аккуратный путь — `scp` с локальной машины:

```bash
# С локального ноутбука:
tar czf hidden.tar.gz autoeval/tasks/*/hidden
scp hidden.tar.gz user@server:/opt/autoeval/

# На сервере:
cd /opt/autoeval
tar xzf hidden.tar.gz
rm hidden.tar.gz
```

Альтернативно — закрытый репозиторий только для `hidden/` (если команда поддерживает 2 репо).

### 4. .env

```bash
cd /opt/autoeval/autoeval
cp .env.example .env
nano .env  # вставь OPENROUTER_API_KEY и проверь модели
```

**Безопасность:**
- `chmod 600 .env`
- Не клади в git (`.env` в `.gitignore`).
- Не показывай в логах (`scripts/eval.mjs` уже не печатает ключ).

### 5. Smoke-тест

```bash
npm run eval -- --task 01 --submission fixtures/task01/submission-ok.md
```

Должен пройти за ~3 минуты, выдать `X.X/10`.

Если упало — проверь:
- `node --version` ≥ 20
- `OPENROUTER_API_KEY` валиден (curl-тест на `https://openrouter.ai/api/v1/auth/key`)
- `tasks/01-clear-prompt/hidden/tests.yaml` существует и валидный YAML

### 6. (Опционально) HTTP-обёртка

Для команды Александра — простой HTTP-эндпоинт «отправь сдачу — получи балл».
В v1 этого нет (это уже следующий проект — «платформа»). Но если очень нужно:

```bash
# Самое простое — Express-обёртка вокруг scripts/eval.mjs:
npm install express multer
# написать routes/eval.js: POST /eval — multipart [task, file]
# вызывает spawnSync('node', ['scripts/eval.mjs', '--task', N, '--submission', path])
# возвращает report.json как ответ
```

ИЛИ — Telegram-бот: кандидат шлёт сдачу боту, бот зовёт `eval.mjs`, отдаёт балл.
Это уже зона **assistant-hub** (основного проекта), фазы D1+.

### 7. Бэкапы

- `tasks/*/hidden/` — раз в неделю в защищённое хранилище.
- `submissions/` (сдачи кандидатов) — по политике ПДн (см. PROJECT.md основного проекта).
- `.env` — НЕ в бэкапы.

## Обновление тест-сетов

Когда команда хочет освежить кейсы (раз в квартал):

1. Правишь `tasks/NN/hidden/tests.yaml` локально.
2. Гоняешь калибровку (`npm run eval` на эталонных сдачах) — балл не должен сильно скакнуть.
3. Через `scp` переносишь на сервер.
4. Перезапуск ничего не требует — скрипт читает yaml на каждый прогон.

## Известные риски прода

| Риск | Митигация |
|---|---|
| OpenRouter упал | Скрипт упадёт с явной ошибкой. Откладываем проверку. |
| Лимит токенов исчерпан | Мониторь баланс OpenRouter, ставь алерт. |
| Кандидат прислал гигантскую сдачу | `judge.mjs` уже режет лог до 12000 символов. Финал-блок не режется — может улететь в overflow, см. TODO. |
| Утечка `hidden/` через `git add` по ошибке | `.gitignore` плотный. Перед `git push` обязательный `git status` (см. CLAUDE.md проекта). |

## Что точно НЕ деплоить на этом этапе

- Публичный веб-интерфейс «кандидат загружает → балл». Это полноценная «платформа», отдельный проект.
- Авто-приём через Telegram-бот. Тоже отдельная зона (фаза D1+ в `assistant-hub`).
- Хранилище сдач в облаке. v1 — локально.
