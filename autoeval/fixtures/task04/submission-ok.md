# Сдача — Task 04 (JSON-экстрактор отладка) — хорошая версия

### ФИНАЛ

Ты — экстрактор полей из писем-заявок. Извлеки из текста письма JSON со следующими ОБЯЗАТЕЛЬНЫМИ полями:

```
{
  "name": "string | null",
  "company": "string | null",
  "contact": "string | null",
  "amount": "number | null",
  "deadline": "string | null",
  "urgent": "boolean"
}
```

ЖЁСТКИЕ ПРАВИЛА:

1. Возвращай ТОЛЬКО JSON. Никаких комментариев до, после или внутри JSON. Никакого markdown — никаких ```json и никаких ```. Если что-то непонятно — ставь `null`, НЕ объясняй.

2. Если поле явно не указано в письме — ставь `null`. НЕ выдумывай. НЕ выводи название компании из домена email. НЕ угадывай имя из контекста.

3. Если в письме упомянуты ДВЕ суммы (например: «прошу скидку с 80000 до 50000», «стоимость 100000, депозит 30000»):
   - бери ЦЕЛЕВУЮ (финальную) сумму = ту, которую клиент хочет ИТОГО заплатить или которая является итоговой стоимостью сделки.
   - при «скидке с X до Y» — бери Y (Y = что клиент хочет).
   - при «всего X, депозит Y» — бери X (X = итоговая стоимость).

4. `urgent = true` если в письме явно есть: «срочно», «горит», «asap», «вчера надо было», «нужно к завтра», ИЛИ если срок выпадает на следующие 3 календарных дня от сегодняшней даты (2026-05-26).

5. `deadline` — в формате `YYYY-MM-DD`. Если дата размытая («до конца недели», «в течение месяца») — ставь null.

6. `contact` — email или телефон. Один. Если оба — предпочти email. Формат номера — как написан в письме.

Письмо:
{{input}}

### ЛОГ

**Дефект 1 — модель выдумывает поля, которые не указаны.**
Симптом: на тренировочном письме №1 («Здравствуйте, подскажите цены...») модель в `company` вставила «Ромашка», хотя в письме компании не было.
Причина: в сломанном промпте было «постарайся вывести из контекста (например, по корпоративной почте — название компании из домена)». Это прямая команда выдумывать.
Починка: убрал эту фразу, добавил жёсткое «Если поле явно не указано — ставь `null`. НЕ выдумывай. НЕ выводи компанию из домена.»
Замер: после правки на 8 тренировочных — 0 случаев выдумывания vs 3 до правки.

**Дефект 2 — модель добавляет комментарии в JSON.**
Симптом: на письме №3 модель выдала `{ "name": "Иван", ... } // примечание: имя могло быть и в подписи` — это ломает `JSON.parse`.
Причина: в сломанном промпте было «если что-то непонятно — поясни в ответе как принял решение». Это прямой призыв к комментариям.
Починка: убрал. Добавил «Возвращай ТОЛЬКО JSON. Никаких комментариев. Если непонятно — ставь null, НЕ объясняй.»
Замер: после правки на 8 тренировочных — 0 случаев комментариев vs 2 до.

**Дефект 3 — модель путается с двумя суммами.**
Симптом: на письме №5 («Стоимость 100 тысяч, депозит 30 тысяч сегодня») модель брала 30000 как `amount`.
Причина: в сломанном промпте про суммы было только «число в рублях, без 'руб'». Нет инструкции какую брать.
Починка: добавил пункт 3 с явными правилами «итоговая сумма», «при скидке с X до Y — бери Y», «при депозите — бери полную».
Замер: после правки на 4 тренировочных с двумя суммами — 4/4 правильно vs 1/4 до.

**Дефект 4 — модель оборачивает JSON в ```.**
Симптом: на письме №7 модель выдала ```json\n{...}\n``` — `JSON.parse` ломается без предобработки.
Причина: в сломанном промпте было «Верни результат в виде JSON» без оговорки про markdown.
Починка: добавил «Никакого markdown — никаких ```json и никаких ```.»
Замер: после правки на 8 тренировочных — 0 случаев обёртки vs 3 до.

**Проверка что не сломал рабочее:** прогнал v4 (финал) на всех 8 тренировочных — 8/8 корректный JSON, все эталонные значения совпадают. v1 (сломанная) давала 2/8.
