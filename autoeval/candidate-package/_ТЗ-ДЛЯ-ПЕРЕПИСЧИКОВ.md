# ТЗ для переписчиков курса-теста для ассистентов

Адресовано команде из 9 переписчиков. Один человек = одна задача. Десятый переписчик — общий документ «Как сдавать».

Читать сверху вниз. Все разделы обязательны. Если что-то вступает в противоречие с текущим документом — побеждает этот ТЗ.

---

## 0. КОНТЕКСТ ЗА 30 СЕКУНД

Мы тестируем кандидатов на роль бизнес-ассистента через 9 учебных задач по настройке ИИ. Кандидаты — НЕ программисты, обычные люди (бывшие маркетологи, бухгалтеры, рекрутеры). Сейчас задания написаны как у Большой Серьёзной Корпорации: длинно, с теорией, с бюрократией, без помощи когда застрял. Кандидат открывает HTML и закрывает через 30 секунд от объёма.

Нужно переписать так, чтобы получился **тест-обучатор**: документ, который пока проходишь — попутно учит. Кандидат должен ловить кайф, а не уставать.

---

## 1. ОБЩАЯ ФИЛОСОФИЯ

**В одной фразе.** Каждый HTML-файл задачи — это короткий полезный тренажёр, а не корпоративная методичка. Кандидат заходит, через 30 секунд понимает что делать, через час сдаёт и чувствует что узнал что-то полезное.

**5 принципов (выполнять все, отказ от любого = переделка):**

1. **Дружелюбный тон.** Как современный EdTech-курс (Yandex Practicum, Hexlet), а не как HR-портал. На «ты». Без эмодзи. Без «уважаемый кандидат». Без красных danger-блоков.
2. **Минимум воды.** Сценарий — 100 слов. Введение — 80. Если можно убрать абзац без потери смысла — убрать.
3. **Помощь когда застрял.** Каждая задача содержит блок «Если застрял» с 3-5 рабочими подсказками. Не «подумай ещё раз», а «попроси ИИ сделать X фразой Y».
4. **Прогресс видно.** Прогресс-бар сверху каждой страницы. Кандидат всегда знает где он, сколько осталось, что дальше.
5. **Фишки удержат мотивацию.** Совет дня в углу, бейдж навыка в финал-экране, оценка времени, кнопка перехода к следующей задаче. Мелкие награды — не дают закрыть документ.

**Антипринцип.** Не «больше теории — выше качество». Наоборот: **чем короче — тем лучше**.

## 2. СТРОГИЕ ЛИМИТЫ И СТРУКТУРА КАЖДОЙ ЗАДАЧИ

Жёсткий каркас. Все 9 задач строятся по одной структуре, в одном порядке. Никаких импровизаций со структурой.

### 2.1. Шапка страницы (сверху каждого файла)

В шапке три элемента, в указанном порядке:
1. **Прогресс-бар.** «Задача N из 9» + 9 кругов, первые N-1 закрашены, текущий — выделен рамкой. См. раздел 3.1.
2. **Заголовок задачи.** Одна строка: «Задача N. Название». Без подзаголовков.
3. **Оценка времени.** «Время на задачу: ~40-60 минут». Реалистичная, не страшная.

### 2.2. Введение / мотивация
- **Лимит: 80 слов МАКСИМУМ.** Считать слова.
- Одна цель: за 3 предложения объяснить «зачем эта задача в жизни». Не «чему ты научишься» (это в финале), а «когда в реальной работе ассистента это пригодится».
- Без слов «навык», «компетенция», «инжиниринг» в этом блоке. Простыми словами.

### 2.3. Сценарий
- **Лимит: 100 слов МАКСИМУМ.**
- Одна конкретная ситуация. Кто, что, какая боль. Без двух раундов «а вот ещё вариант».
- Заканчивается одной фразой: «Твоя задача — [что сделать]».

### 2.4. Материалы для тренировки (СВЁРНУТЫЕ ПО УМОЛЧАНИЮ)
- Это самая объёмная часть текущих документов. **Прячем в свёрнутый блок** HTML `<details>`.
- Заголовок свёрнутого блока: **«Посмотреть материалы для тренировки»**.
- Внутри — без изменений: правила формата, эталонные пары, тренировочные тексты, JSON-схемы и т.д. — что было.
- Если внутри несколько типов материалов (правила + пары + статья) — каждый в своём вложенном `<details>` с понятным названием.
- **Важно.** Содержательно ничего не выкидывать — это нужно для решения. Только скрыть из первого экрана.

### 2.5. Что нужно сделать
- **Формат: ЯВНЫЙ план из 4-6 шагов.** Не свободный текст, а нумерованный список.
- **Каждый шаг = 1-2 предложения.** Не больше.
- Начинать каждый шаг с глагола в повелительном наклонении: «Открой», «Прогони», «Сравни», «Перепиши», «Замерь».
- Пример (для задачи 1):
  1. Открой материалы для тренировки выше и прочитай правила формата.
  2. Напиши черновой промпт — на «глаз», как чувствуешь. Если трудно — см. блок «Если застрял».
  3. Прогони его на тренировочной статье. Сравни результат с правилами.
  4. Заметил что не так — переделай конкретный пункт промпта. Минимум 3 версии.
  5. Открой шаблон ответа и заполни две секции.

### 2.6. Если застрял
- **Новый раздел.** Сейчас его НЕТ ни в одной задаче — это и есть главная переделка.
- **3-5 конкретных подсказок-фраз.** Не «попробуй ещё раз», а готовые формулировки.
- Каждая подсказка = одно действие или одна фраза для ИИ, обёрнутая в `<code>` или в `<blockquote>`.
- Примеры подсказок для задачи 1:
  - «Не знаешь с чего начать промпт — попроси ИИ: *«Напиши мне инструкцию для саммари статьи по этим правилам: [вставь правила]. Лимит 200 слов»*. Это первый черновик, его потом будешь править.»
  - «Промпт срывается на одной из 5 эталонных пар — скопируй пару в чат и попроси: *«Вот эталон. Перепиши мою инструкцию так, чтобы её результат был ближе к эталону»*.»
  - «Не понимаешь почему модель добавляет имя автора — добавь в промпт явный блок «Что НЕ упоминать». Запреты работают сильнее правил.»
- Эти подсказки — и есть тест-обучатор. Кандидат, который застрял, прочитает подсказку и пойдёт пробовать. Тот, кто не застрял — пройдёт мимо.

### 2.7. Короткий путь (фишка-хак)
- **Один абзац, 2-3 предложения.**
- Объясняет «как сделать быстро». Признаёт что это не зашквар.
- Пример (задача 1): *«Если хочешь начать быстро — попроси ИИ сгенерировать первую версию промпта по описанию из материалов. Это не считается читом, это нормальный подход. Дорабатывай уже его — будет в разы быстрее чем писать с нуля.»*
- Этот блок снимает страх «я не достаточно умный» — он часть тест-обучатора.

### 2.8. Что прислать
- **Лимит: 60 слов МАКСИМУМ.**
- Очень коротко: один файл, две секции — ФИНАЛ и ЛОГ. Что в каждой — одной строкой.
- Не дублировать структуру шаблона, она в шаблоне.
- Заканчивается ссылкой/кнопкой: «Скачать шаблон ответа →» (см. 3.5).

### 2.9. Как оценим
- **Лимит: 1-2 предложения.**
- Без подробностей про ассерты, LLM-судью, рубрики. Это техническая кухня.
- Например: «6 баллов даёт автопроверка финала на скрытых примерах. 4 балла — за качество процесса в логе. Итого 10.»

### 2.10. Финал-экран
- **Лимит: 2-3 предложения позитивной нейтральной обратной связи.**
- Тон: «ты сделал что-то полезное».
- Без коучингового «ты молодец» и без обещаний «ты теперь профи».
- Содержит **бейдж навыка** (см. 3.3): «Получи навык: Стабильные промпты для повторяющихся задач».

### 2.11. Подвал
- Две кнопки/ссылки: **«← Предыдущая задача»** и **«Следующая задача →»**.
- Для задачи 1 — только «Следующая». Для задачи 9 — только «Предыдущая» + «Все задачи».
- Дополнительно — «К списку задач» по центру.

## 3. ОБЯЗАТЕЛЬНЫЕ ФИШКИ ИНТЕРФЕЙСА

Эти элементы добавляем в КАЖДУЮ из 9 задач. Без них задача не принята.

### 3.1. Прогресс-бар сверху

HTML и CSS — простой блок из 9 кругов в ряд. Первые `N-1` закрашены, `N`-й выделен (рамка/цвет), остальные пустые. Над кругами — текст «Задача 3 из 9».

```html
<div class="progress">
  <div class="progress-label">Задача 3 из 9</div>
  <div class="progress-dots">
    <span class="dot done"></span>
    <span class="dot done"></span>
    <span class="dot current"></span>
    <span class="dot"></span>
    <span class="dot"></span>
    <span class="dot"></span>
    <span class="dot"></span>
    <span class="dot"></span>
    <span class="dot"></span>
  </div>
</div>
```

CSS — единый для всех задач (см. раздел 9.1).

### 3.2. Оценка времени

В шапке после заголовка одной строкой: **«Время на задачу: ~40-60 минут»**. Точные числа — на усмотрение переписчика, но в диапазоне 30-90 минут. Не «1 час 30 минут» — это пугает.

### 3.3. Бейдж навыка в финал-экране

В финал-экране внизу — выделенный блок:

```html
<div class="skill-badge">
  <div class="skill-label">Навык освоен</div>
  <div class="skill-name">Стабильные промпты для повторяющихся задач</div>
</div>
```

Названия навыков по задачам (использовать буквально):
1. Стабильные промпты для повторяющихся задач
2. Подбор примеров для обучения модели (few-shot)
3. Системный промпт, который держит дух правил
4. Точечная отладка чужих промптов
5. Контекст-инжиниринг — модель отвечает «как ты»
6. Помощник, который не выдумывает (grounding)
7. ИИ, который сначала уточняет, потом делает
8. Промпт-мастер по формуле RICECO
9. Сборка ИИ-конвейера из шагов

### 3.4. Совет дня в углу

В правом верхнем углу страницы — небольшая карточка с одной фразой-инсайтом. Не перекрывает контент, скрывается на узких экранах.

Тексты советов (1 на задачу, использовать буквально):
1. «Хороший промпт описывает поведение модели в числах и стоп-листах, а не общими словами.»
2. «Эталонные примеры в промпте — это не украшение, а лекция для модели. Выбирай примеры, которые учат разному.»
3. «Запреты вкладываем в принцип, а не в длинный список «не делай». Принцип переживает новые ситуации.»
4. «Чужой промпт чинят строчкой, а не переписыванием. Сломать рабочее — хуже, чем не починить сломанное.»
5. «Контекст-пак собирай не по полноте, а по точкам, где модель обычно врёт.»
6. «Если факта нет в твоём источнике — модель должна честно сказать «не знаю». Это и есть grounding.»
7. «Хороший ИИ-ассистент сначала спрашивает, потом делает. Как живой человек.»
8. «Промпт можно поручить написать промпту. Это не магия, это просто следующий слой.»
9. «Конвейер из коротких шагов — устойчивее одного большого промпта. Каждый шаг чинится отдельно.»

### 3.5. Кнопка «Скачать шаблон ответа»

Внизу страницы, заметная (большая, контрастная):

```html
<a class="template-btn" href="шаблон-ответа-задача-01.md" download>
  Скачать шаблон ответа →
</a>
```

Указать правильный номер шаблона.

### 3.6. Подвал-навигация

См. 2.11. Две кнопки (или одна для крайних задач) + центральная ссылка «Все задачи».

## 4. ТОН РЕЧИ

Жёсткие правила, проверять каждое предложение.

- **Обращение на «ты»** с заглавной только в начале писем / абзацев (как в современных EdTech-курсах).
- **Без эмодзи в тексте.** Совсем. Даже в финал-экране. Даже один.
- **Без бюрократии.** Перевод запрещённых слов:
  - «сдавай» → «пришли»
  - «обязательно» → «нужно»
  - «зачтётся» / «не зачтётся» → «прошла проверку» / «не прошла»
  - «дедлайн» → «срок»
  - «не допускается» → «не нужно делать»
  - «требуется» → «нужно»
  - «информируем» / «сообщаем» / «уведомляем» — убрать вообще
  - «утверждённый», «согласованный», «регламентированный» — убрать
- **Короткие предложения.** Если можно сказать одной фразой вместо двух — сократить.
- **Без воды-связок.** Убирать «стоит отметить», «важно понимать», «как уже было сказано», «обратите внимание».
- **Без коучинга.** Никаких «ты молодец», «у тебя получится», «верь в себя». Тон ровный взрослый.
- **Без страшилок.** Не «иначе автопроверка не зачтёт», а нейтрально «иначе проверка не пройдёт».

### 4.1. Чек-лист тона перед сдачей

Переписчик перед сдачей задачи прогоняет тест:

1. Найди в задаче слова из списка запретов выше — должно быть 0.
2. Найди эмодзи — должно быть 0.
3. Найди предложения длиннее 25 слов — должно быть не больше 3 на весь документ.
4. Найди слова «обязательно», «нужно», «надо», «следует», «должен» — должно быть не больше 5 на весь документ.

## 5. ШАБЛОНЫ ОТВЕТА — НОВЫЙ ФОРМАТ

Все 9 шаблонов (`шаблон-ответа-задача-NN.md`) переписываются по этому формату. Без исключений.

### 5.1. Структура шаблона

```markdown
# Задача N. [Название задачи]

Имя: ___
Дата сдачи: ___
Время потрачено (примерно): ___


### ФИНАЛ

[Здесь — секция с явными подсказками что и куда вставлять. См. 5.2.]


### ЛОГ

[Здесь — анкета на 3 версии. См. 5.3.]


---

Готово. Назови файл `task-N-имя-фамилия.md` и отправь вместе с остальными задачами одним архивом.
```

### 5.2. Секция ФИНАЛ — явные подсказки

**Главная переделка шаблонов.** Сейчас в секции ФИНАЛ написано «вставь свой финальный промпт» — этого мало. Кандидат не понимает что куда.

Делаем явные подразделы с подсказками для КАЖДОЙ задачи (свои подразделы — у каждой задачи под её специфику).

**Пример для задачи 1:**

```markdown
### ФИНАЛ

Текст промпта (тот, что в итоге используешь):
___

Формат вывода, который должен выдавать ИИ (TL;DR / тезисы / выводы — скопируй из правил задачи или опиши свой):
___

Стоп-лист (что модель НЕ должна делать — перечисли):
___

Где подставляется статья (по умолчанию — `{{input}}`, проверь что есть в промпте):
___
```

**Пример для задачи 4 (отладка):**

```markdown
### ФИНАЛ

Починенный промпт целиком (один блок, готовый к копированию):
___
```

**Пример для задачи 8 (промпт-мастер):**

```markdown
### ФИНАЛ

Мета-промпт целиком (тот, в который кидают описание задачи):
___

Что у тебя в нём про каждый из 6 элементов RICECO (по 1 строке):
- Role: ___
- Instruction: ___
- Context: ___
- Examples: ___
- Constraints: ___
- Output: ___
```

**Принцип.** Каждое поле — это один конкретный вопрос. Кандидат отвечает в строку. Не «свободный текст про твой подход».

### 5.3. Секция ЛОГ — анкета на 3 версии

Сейчас в шаблоне написано «расскажи про процесс». Слишком свободно — кандидат пишет 3 строки или 3 страницы.

**Новая структура — сетка-анкета:**

```markdown
### ЛОГ

## Версия 1

Что было (вставь промпт или опиши кратко):
___

Что не работало (на каких тренировочных примерах сломалось, как именно):
___

Что меняю для версии 2:
___


## Версия 2

Что было:
___

Что не работало:
___

Что меняю для версии 3:
___


## Версия 3 (финальная)

Что было:
___

Что получилось (на каких тренировочных примерах всё прошло):
___


## Главный инсайт от задачи (1-2 предложения)

___
```

**Если кандидат сделал с 1 попытки:**

```markdown
### ЛОГ

## Защита одной попытки

Какие риски я предвидел в формулировке промпта:
___

На каких тренировочных примерах проверил:
___

Почему уверен в стабильности на скрытых примерах:
___
```

Эта структура в каждом шаблоне адаптируется под специфику задачи (например, в задаче 4 — отладка 4 дефектов, там сетка идёт по дефектам, а не по версиям).

### 5.4. Финал шаблона

Одна короткая строка:

```markdown
Готово. Назови файл `task-N-имя-фамилия.md` и отправь вместе с остальными задачами одним архивом.
```

Без «Куда отправить: ...» с подробностями — общая инструкция в КАК-СДАВАТЬ.

## 6. ФИШКИ-ХАКИ ДЛЯ КАНДИДАТА

Это блок «Если застрял» + «Короткий путь» из раздела 2. Но усиливаю отдельно — это сердце тест-обучатора.

### 6.1. Готовые фразы для разговора с ИИ

В каждой задаче в блоке «Если застрял» — **1-2 готовые фразы**, обёрнутые в `<code>` или цитатный блок. Кандидат может скопировать-вставить.

Примеры по задачам:

**Задача 1:**
- *«Дай мне инструкцию для саммари статьи с лимитом 200 слов, стоп-листом авторов и форматом TL;DR + 3 тезиса + 3 вывода.»*
- *«Вот моя инструкция и вот эталон. Скажи, почему мой результат хуже эталона, и как переписать инструкцию.»*

**Задача 2:**
- *«У меня 10 пар черновик-готовое письмо. Из них надо выбрать 5 для few-shot. Какой принцип отбора, чтобы избежать дублей?»*
- *«Вот пара X и пара Y. Учат ли они модель разному или это дубль?»*

**Задача 3:**
- *«У меня есть 10 правил школы. Помоги превратить их в системный промпт, который держит дух, а не букву.»*
- *«Вот моё контрольное сообщение и ответ модели. По какому правилу нарушение, и как закрыть дыру принципом?»*

**Задача 4:**
- *«Вот сломанный промпт и эталон. На письме N модель выдала Y вместо Z. Какая фраза в промпте за это отвечает?»*

**Задача 5:**
- *«У меня контекст-пак про эксперта Анну. Прогони его на вопросе X — где модель отвечает «не как Анна»?»*

**Задача 6:**
- *«Вот конспект курса (источник правды) и вопрос студента. Дай ответ строго по конспекту, если ответа нет — скажи «в заметках нет».»*

**Задача 7:**
- *«Размытый запрос: «подготовь презентацию». Какие 3-5 критичных уточнений нужны до выполнения?»*

**Задача 8:**
- *«Напиши промпт по формуле RICECO для задачи: [опиши свою задачу одной фразой].»*

**Задача 9:**
- *«У меня цепочка из 4 промптов. Финальный ответ плохой. Помоги локализовать — какой из 4 шагов виноват?»*

### 6.2. «Короткий путь»

Один абзац в каждой задаче, объясняющий быстрый способ. Без оценочного «это правильно» — просто «это работает».

См. 2.7 — там пример для задачи 1. По аналогии для всех остальных.

## 7. ОБЩИЙ ДОКУМЕНТ «КАК СДАВАТЬ»

Переписать **`КАК-СДАВАТЬ.html`** под жёсткие правила.

### 7.1. Лимит

**Максимум 500 слов на весь документ.** Сейчас сильно больше.

### 7.2. Структура — 3 простых шага

Заменить все разделы на 3 коротких блока:

**Шаг 1. Открой задачу.**
Открываешь HTML-файл задачи, читаешь сценарий и шаги. Внутри — материалы для тренировки. Никаких ограничений на ИИ: ChatGPT, Claude, Gemini — что удобно.

**Шаг 2. Заполни шаблон.**
Скачиваешь `шаблон-ответа-задача-N.md`, заполняешь две секции: ФИНАЛ (готовый промпт) и ЛОГ (3 версии или защита одной попытки). Заголовки секций не меняй — они нужны для автопроверки.

**Шаг 3. Упакуй и пришли.**
9 заполненных файлов → одна папка → ZIP-архив `сдача-имя-фамилия.zip` → отправь в Telegram или ссылкой на Диск тому, кто давал задание.

### 7.3. Что убрать
- **Красный danger-блок** про «Очень важно. Не удаляй заголовки». Заменить на нейтральный блок-«важно» (жёлтый/серый, без восклицаний).
- Длинную таблицу имён файлов — заменить одной строкой: «Имена файлов: `task-NN-имя-фамилия.md`. Пример: `task-01-ivan-petrov.md`».
- Раздел «Что нельзя» — оставить 1-2 пункта максимум, без угроз («лог разоблачит»). Например: «Можно использовать любого ИИ — это не чит, это часть навыка. Главное — заполни лог осмысленно, без него процесс не зачтётся.»
- Раздел «Что будет дальше» — оставить одну строку: «Через ~20 минут после получения архива пришлём профиль из 9 баллов и комментарии.»

### 7.4. Тон
- На «ты», без «уважаемый кандидат».
- Без эмодзи.
- Дружелюбно-нейтрально: «вот как это работает», а не «вы обязаны».

## 8. ЧЕМ КОРОЧЕ — ТЕМ ЛУЧШЕ

**Когда сомневаешься — выкидывай.**

### 8.1. Что можно убрать в задаче (если есть)
- Дублирующие абзацы в «Сценарии» (часто 3 абзаца — реально нужен 1).
- Раздел «Что мы даём» как отдельный заголовок — он сейчас просто введение к материалам. Эти материалы — внутри свёрнутого блока (раздел 2.4), заголовок не нужен.
- Подробные обоснования «зачем это в реальной работе» — это в финал-экране, не в начале.
- Примеры структуры файла ответа в HTML — это в шаблоне, не дублировать.
- Длинные раскладки «Как пользоваться эталонами» — кандидат и так понимает.

### 8.2. Что можно убрать в шаблоне (если есть)
- Подсказки в скобках типа «(впиши своё имя сюда)» — заменить на «___» (см. 5.2).
- Длинные инструкции «Не переписывай всё с нуля. Каждое исправление должно быть точечным» — это в задаче, не в шаблоне.
- Дублирующие напоминания «Сохрани файл с именем...» (одной строки в конце достаточно).

### 8.3. Метрика «короче»

Финальная задача в HTML — **не больше 250 строк** (сейчас 400-500). Считать с CSS включённым. Если не получается ужать — значит, материалы для тренировки слишком длинные и можно ещё что-то прятать вложенными `<details>`.

## 10. ЧЕК-ЛИСТ САМОПРОВЕРКИ ПЕРЕД СДАЧЕЙ

Каждый переписчик прогоняет по своей задаче перед сдачей:

1. [ ] Введение / мотивация — ≤80 слов.
2. [ ] Сценарий — ≤100 слов.
3. [ ] Все объёмные материалы — в `<details>` с заголовком «Посмотреть материалы для тренировки».
4. [ ] План шагов — нумерованный список из 4-6 пунктов, каждый ≤2 предложений.
5. [ ] Блок «Если застрял» — есть, 3-5 подсказок, есть хотя бы 1 готовая фраза-цитата для ИИ.
6. [ ] Блок «Короткий путь» — есть, 1 абзац.
7. [ ] «Что прислать» — ≤60 слов.
8. [ ] «Как оценим» — ≤2 предложений, без технических деталей.
9. [ ] Финал-экран — 2-3 предложения, есть бейдж навыка.
10. [ ] Прогресс-бар сверху — есть, правильное число закрашенных кругов.
11. [ ] «Время на задачу» — указано.
12. [ ] Совет дня в углу — есть, текст из 3.4.
13. [ ] Кнопка «Скачать шаблон ответа» — есть, ссылка правильная.
14. [ ] Подвал с навигацией — есть.
15. [ ] Использован единый CSS из 9.1, нет разноцветных «уникальных» стилей.
16. [ ] Тон проверен по 4.1 (нет запрещённых слов, нет эмодзи, нет коучинга).
17. [ ] Общий размер задачи — ≤250 строк HTML.
18. [ ] Шаблон ответа переписан по 5.1-5.4 с явными подразделами под специфику задачи.

## 11. ЧТО НЕ ТРОГАТЬ

Чтобы не сломать систему проверки:

- **Названия секций в шаблонах**: строго `### ФИНАЛ` и `### ЛОГ`. Английские синонимы `### FINAL` / `### LOG` — допустимы, но русские предпочтительны.
- **Содержание тренировочных материалов** (правила формата, эталонные пары, JSON-схемы, тексты статей, конспекты курсов) — не редактировать, не сокращать, не «улучшать». Только перенести в свёрнутые блоки.
- **Имена файлов**: `task-NN-имя-фамилия.md`. `NN` с ведущим нулём для 01-09.
- **Переменную `{{input}}`** в шаблонах и описаниях — не переименовывать.
