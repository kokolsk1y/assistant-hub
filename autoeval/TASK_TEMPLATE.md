# Шаблон задачи (что должен сдать агент)

Каждая из 9 задач лежит в `autoeval/tasks/NN-slug/` со следующими файлами.

## Обязательные файлы

```
tasks/NN-slug/
├── task.md                     # Описание задачи для кандидата (Markdown, ru)
├── training/                   # Открытые материалы (кандидат видит)
│   ├── examples.md             # Тренировочные примеры с эталонами
│   └── (broken-prompt.md)      # Сломанный промпт — только для задач 4 и 6
├── hidden/                     # Скрытые тест-сеты (gitignored)
│   ├── tests.yaml              # ≥15 кейсов с эталонами (vars + assert)
│   └── README.md               # Замечания по тест-сету (что ловит каждый блок)
└── promptfooconfig.yaml        # Главный конфиг для promptfoo
```

## Структура `task.md`

Шаблон. Все 9 задач следуют одинаковому формату.

```markdown
# Задача N: <Название>

> 📌 **Главное в этой задаче.** <одна фраза-фокус>

## Сценарий
<бизнес-кейс на синтетических данных, 2-4 абзаца>

## Что даём
- <список материалов: training/examples.md, броненосец если есть>

## Что нужно сдать
**Финал-блок** (обязательно начинается со строки `### ФИНАЛ` или `### FINAL`):
<какая конфигурация — промпт / системный промпт / контекст-пак>

**Лог процесса** (обязательно начинается со строки `### ЛОГ` или `### LOG`):
- ≥3 версии конфигурации с пояснением, какие замеры толкнули к правке;
- ИЛИ — если результат ≥5/6 с одной попытки — обоснование почему хватило.

## Метрика
- **6 баллов** = автопроверка на 15-20 скрытых кейсах (см. ниже);
- **4 балла** = LLM-судья по логу (4 бинарных пункта × 1 балл, либо «защита одной попытки»).

## Финал-экран (после балла)
- **Нейтральный блок:** <одинаковый текст про навык, для всех>
- **Персональный блок:** <зависит от балла, мягкий тон даже при провале>
```

## Структура `promptfooconfig.yaml`

```yaml
description: "Task NN — <slug>"

providers:
  - id: ${PROMPTFOO_TARGET_MODEL}

# Промпт кандидата подкладывается оркестратором в этот файл.
# Кандидат сам пишет финальный промпт — мы только подмешиваем переменные кейса.
prompts:
  - file://_submission_prompt.txt

# Скрытые кейсы. Каждый — vars + assertions.
tests:
  - file://hidden/tests.yaml

# Дефолтные ассерты, которые относятся ко всем кейсам.
defaultTest:
  options:
    provider:
      id: ${PROMPTFOO_JUDGE_MODEL}
  assert: []
```

## Структура `hidden/tests.yaml`

```yaml
# tests.yaml — массив тест-кейсов promptfoo.
# Каждый кейс = {description, vars, assert}.
- description: "Кейс 1: <короткое описание грани>"
  vars:
    input: "<входные данные кейса — статья, письмо, вопрос>"
  assert:
    - type: javascript
      value: "output.length <= 200"
    - type: not-contains
      value: ["автор-имя", "название-статьи"]
    - type: llm-rubric
      value: "Ответ структурирован как TL;DR + 3 тезиса + 3 вывода и не содержит фактов, которых нет во входе."

- description: "Кейс 2: ..."
  ...
```

## Что НЕ делаем агенту

- Не пишем реальные ИИ-промпты, которые сам кандидат должен сочинить. **Это его работа.**
- Не выдаём в `training/` ответы на `hidden/`-кейсы.
- Не используем эмодзи / маркетинговый язык / западные имена в кейсах — всё на русском, реалистичные ситуации российской онлайн-школы / консультанта / B2B-бизнеса.
