1. По одному fix-агенту на задачу с конкретным списком багов.

3. Программный sweep всех `tests.yaml` на оставшиеся структурные баги.

### Раунд 4: финальная калибровка
1. Перепрогон всех 4 fixture после фиксов.
2. Программный фикс multi-line JS без `return` в task02 (16), task04 (26), task07 (30) — итого 72 ассерта.
3. Финальная проверка: **0 contains-со-списком, 0 multi-line JS без return**.

## Найденные и исправленные баги (полный список)

### Архитектурные (`scripts/eval.mjs`, `scripts/judge.mjs`)

| # | Баг | Фикс |
|---|---|---|
| A1 | `\b` в regex парсера сдач не работает с кириллицей | Negative lookahead `(?![а-яёa-z])` |
| A2 | Promptfoo не подставляет `${VAR}` в provider.id | `substituteEnv()` в оркестраторе |
| A3 | `spawnSync` с `.cmd` на Windows возвращает exit=null | `shell: true` |
| A4 | Race condition при параллельных прогонах одной задачи | Уникальное имя файла `_*_<runId>.yaml/txt/json` |
| A5 | `scoreFromResults` не различает failed assertion и сетевую ошибку | Только `gradingResult.error` считаем как provider error |
| A6 | `Promise.all` в `judgeTask09` падал при сбое одной из 2 рубрик | `Promise.allSettled` + fallback |
| A7 | `safeJson` падал на нестандартном ответе модели | 3-уровневый recovery (raw → cleaned → regex extract) |
| A8 | Promptfoo возвращает exit 100 при failed-кейсах — это **нормально**, не ошибка | Обработка `status === 100` как валидной |
